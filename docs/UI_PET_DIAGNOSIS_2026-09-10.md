# 本机参数、启动日志和宠物滚动条排查

## “读取本机默认值”的实际范围

按钮从当前 AiBrowser 管理客户端读取时区、屏幕可用逻辑尺寸，并切换部分指纹选项：Canvas、WebGL、WebGPU、Audio、WebRTC 等设为真实，地理位置设为禁用。它不启动 Google Chrome，不读取 Chrome 的配置文件或登录数据，也不把所有指纹选项恢复为原生。

屏幕尺寸不是显示器物理像素数，会受到系统缩放及远程显示设置影响。空白 User-Agent 在 Chromium 分支按环境自动生成；Firefox-Reverse 的 UA 由该内核管理。电池、CPU、内存等其他设置仍须在指纹配置中检查。

已把按钮改为“读取本机基础参数”，补充范围说明，纠正摘要中硬编码的 Google Chrome / Chrome 默认，以及按钮未实际切换系统语言的问题。

## “引擎启动 · 3 个浏览器可用”的实际范围

数字来自 `info.browsers.length` / `engine.candidates()`，统计检测到的浏览器可执行程序候选路径，例如内置内核、系统 Chrome 或 Edge。它不是用户创建的环境数量，检测到路径也不代表已验证每个程序能成功启动。日志是启动时记录，不随后来创建环境更新。

已改成“引擎启动 · 检测到 N 个浏览器程序”。该记录本身不表示用户的第 4 / 第 5 个环境丢失；本次没有读取用户账号内容来核验具体环境数据。

## 3D 宠物导致桌面边缘出现无法拖动的滚动条

确认了可以在本地独立复现的代码缺陷：

1. 宠物宿主是覆盖桌面的透明窗口，页面根节点原先允许内容溢出；固定大小的渲染容器和 1.75 倍动作绘制范围靠近右下角时，会撑出该透明页面自己的滚动条。
2. 宿主在宠物交互区域外让鼠标事件穿透，因此页面边缘的滚动条可见，但鼠标不能正常拖动它。
3. 宿主原先只在创建时获取显示器边界，未监听后续分辨率、DPI、工作区或显示器数量变化。远程会话调整显示参数后，窗口和交互坐标可能继续使用旧值。

这不等于宠物修改了 Windows 的显示分辨率。相关路径没有修改系统显示模式的操作。用户远程软件本身的滚动行为尚未实测，不能将其全部归因于上述缺陷。

修复包括固定根页面并裁剪桌面外溢出，保留宠物动作的扩展绘制范围；监听显示器变化更新宿主与 renderer 坐标，恢复可见位置，并取消过期拖拽及缩放状态。屏幕变化无需写入磁盘设置。

参考：[Electron 屏幕事件与坐标](https://www.electronjs.org/docs/latest/api/screen)、[MDN overflow](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow)。
