# 环境隐私保护修复说明

本次为 `PRIVACY_ISOLATION_AUDIT_2026-10-02.md` 中启动、代理回退、指纹失败处理和检测页泄露风险的代码修复。默认开启严格隐私模式，保护条件不满足时拒绝启动。旧配置也采用这一默认值；只有显式设置 `privacy.strict: false` 才进入兼容模式。

## 已实现

- 每个环境使用独立本机代理网关，沿用独立用户数据目录、缓存、临时目录和环境锁。网关只能连接已固定的上游桥接器，没有连接目标网站的直连分支。
- 严格模式要求有效 HTTP、HTTPS 或 SOCKS5 代理。系统代理在每次启动时解析为固定端点；PAC、未启用的系统代理、空代理和直接连接均拒绝启动。运行期间不会跟随系统设置改变出口。
- 启动前必须验证出口及其时区。启动时允许依次验证配置的备用代理；运行期间发生代理连接/认证失败后关闭网络，必须重新启动，不能自动变为 DIRECT。
- 浏览器启动时网关关闭。关键指纹覆盖、文档开始脚本、Worker 自动附加及定位权限设置完成后才开放网关。附加失败、脚本异常、读回不一致或 CDP 连接断开时，先同步关闭网关及现有连接，再关闭本环境浏览器。
- 初始及额外启动页面都在指纹注入后导航。严格模式拒绝会话自动恢复，避免旧页面提前执行；原有会话文件保留。
- 严格模式禁止网页地理定位，清除历史定位许可例外；禁用 WebRTC JS 接口及非代理 UDP，关闭 QUIC、DoH、预测和后台联网，禁止浏览器本地解析目标域名。时区和语言不能使用系统真实值，可指定有效自定义时区/语言。
- 读回校验覆盖 UA、平台、语言列表、可配置 CPU/内存、时区，以及可用 WebGL 的配置元数据；页面同时检查 WebRTC 禁用状态。Worker 校验其适用字段。
- 检测页只通过正在运行的环境网关发起严格模式网络探测。网关关闭时拒绝探测，刷新发现 IP/时区变化时关闭网关。旧的宿主 DNS 探测被停用，页面标记“未执行”，不会显示为检测通过。
- 禁止严格模式通过宿主直连提取/刷新动态代理。Mihomo 订阅转换保留监听端口绑定上游，未匹配请求改为 REJECT。
- Firefox 暂无等效指纹注入，严格模式明确拒绝。兼容模式下仍修正了 Firefox 禁止定位/禁用 WebRTC 的首选项；原生指纹模式也尊重禁止定位设置。

## Windows 出站保护与使用

编辑环境 → 代理配置 → 保留“严格隐私保护” → 点击“安装网络保护”。安装会触发 Windows 管理员授权。

保护脚本仅为所选独立内核目录内的可执行文件添加持久出站阻断规则，阻断非回环 IPv4/IPv6；系统浏览器路径禁止安装。不会关闭网卡，不会修改全局出站默认策略，不会修改其他程序规则。安装后的规则在应用退出或崩溃时保留，防止浏览器失去管理进程后直连。使用同一个内核的兼容模式环境也受这些规则约束，直接联网可能被阻止。

每次启动校验防火墙服务、全部网络配置文件及规则的有效范围；运行期间约每 30 秒复核，失败关闭网关。更换/更新内核或移动内核目录后，可能需要重新安装规则。

本机检查结果：Domain、Private、Public 三种 Windows 防火墙配置均为关闭状态，保护检查按预期失败。本次没有修改全局防火墙开关，也没有触发提权安装。需要先在 Windows 安全中心开启防火墙，再安装内核规则。完成前严格模式应阻止启动。

## 验证记录

新增 `npm run selftest:privacy`。验证均使用本机模拟代理、合成 CDP 或独立测试目录，不向公网泄露测试站发送请求。

- `privacy-hardening-selftest.js`：15 组，覆盖安全默认值、前后端一致性、系统代理固定、禁用/PAC 拒绝、备用代理、Mihomo REJECT、网关隔离、HTTP 认证、SOCKS5 远端域名、断线锁定、活动隧道关闭、指纹失败、检测页拒绝直连、出口变化、缺失系统保护。
- `fingerprint-failure-lifecycle-selftest.js`：严格模式页面/Worker 异常与 CDP 断线关闭网关后再停止进程，不恢复失败目标；保留兼容模式生命周期测试。
- 其余 10 个回归脚本：`fingerprint-inject-order-selftest.js`、`automation/fingerprint-native-selftest.js`、`automation/fingerprint-override-regression-selftest.js`、`automation/fingerprint-stability-selftest.js`、`proxy-forwarder-selftest.js`、`automation/isolation-fingerprint-selftest.js`、`proxy-feature-selftest.js`、`network-mode-selftest.js`、`profile-isolation-regression-selftest.js`、`native-fingerprint-engine-selftest.js`。
- Windows PowerShell 5.1 实际执行保护 Check：防火墙关闭时返回失败；未进行安装成功后真实浏览器的出站阻断/抓包验收。

## 仍需明确的边界

1. 这是浏览器环境的数据隔离和出站限制，不是每个环境一台虚拟机。各环境仍共用系统内核、设备与用户权限；不防本机恶意程序、管理员或恶意扩展。防火墙复核不是抵抗管理员实时篡改的机制。
2. 固定的上游必须可信。若 FClash 等本机代理自身选择 DIRECT，或远端代理暴露来源 IP，本项目无法凭一个代理端口保证匿名。需要关闭上游 DIRECT/故障回退，使用稳定出口；旋转代理每次连接都可能改变 IP，单次出口检测不能保证后续地理一致性。入口代理本来就能看到客户端连接来源。
3. Windows 规则目前保护浏览器内核。管理应用的 AI、更新、订阅导入、扩展下载等独立宿主功能不属于每个环境的网络通道，不能据此宣称整台电脑或管理应用所有请求均匿名。
4. 指纹读回验证只覆盖明确列出的字段和已附加执行环境，不构成所有网站、所有浏览器 API、所有 TLS/HTTP 指纹的完整一致性证明。配置选择真实硬件属性、登录已有账号和历史站点数据也可能产生关联。严格模式关闭定位，不能承诺网站无法通过其他渠道推断地区。
5. 目前严格模式仅支持 Windows Chromium；明文 WebSocket Upgrade 被网关拒绝，WSS 走 CONNECT。不能把兼容模式当作同等保护。
6. 正式使用前，在防火墙规则已生效的独立测试环境中验收：正常出口、上游中断/认证失败、关闭管理进程、多个环境同时运行、IPv6、DNS、WebRTC、新标签/跨站 iframe/Worker，以及时区语言和目标站点的指纹读取。当前没有执行这些真实浏览器及抓包验收，不能宣称“零泄露”。
